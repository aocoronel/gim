* gim

This repository contains a wrapper for ~git~ with the goal of managing multiple git repositories, and bring some nice features from ~fossil~.

This is WIP.

** Usage

#+BEGIN_SRC
  Usage: gim [option] command
  Commands:
    addremove
        Stages everything
    all:[CMD]..
        Runs a command in all repositories. Must be ran from a root of git repos
        Pass --dry-run afterwards, if the command supports it
    bundle
        Bundle a repository
    bundle-all
        Bundle all repositories. Must be ran from a root of git repos
    clean
        Clean working tree
    close
        Remove worktree
    commit:[git-option]..
        Stage changes and commit
    not-clean
        Check if any repository is not clean. Must be ran from a root of git repos
    open:path [commit-ish] [git-option]
        Create worktree When using -B flag, omit the branch name
    update
        Update current checkout
  Options:
    C,directory:DIR
        Change directory
    dry-run
        Don't apply changes
    force
        Ignore destructive warnings
    verbose
        Show stdout messages
#+END_SRC

** My workflow

- Create bare repository
- ~gim open trunk~ or ~gim open my-feature -B~
- Do work: ~gim commit -m "message"~...
- ~gim close~

But what happened there? The bare repo, is akin to a ~repo.fossil~, and ~gim open trunk~ opens a worktree with default ~main~ branch. After doing work, if untracked files exist I do ~gim addremove~, then ~gim commit~, otherwise just ~gim commit~. The commit command will: pull changes, stage tracked files, commit and push changes back. Then we close the trunk worktree, by running ~gim close~ within the worktree.
